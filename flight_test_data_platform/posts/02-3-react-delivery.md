# 02-3. 개발한 화면이 사용자에게 전달되기까지

앞선 글에서는 구형 브라우저에 대응하기 위해 JavaScript와 CSS 구성을 조정한 과정을 살펴봤다. 이번에는 개발한 화면을 어떻게 확인하고 배포하는지, 브라우저에서 화면 이동과 그래프가 어떻게 동작하는지 정리하려 한다.

현재 프론트엔드는 React만으로 구성되어 있지 않다. Vite로 개발·빌드를 진행하고, React Router로 화면을 연결하며, Recharts로 데이터를 그래프에 표시한다. 각 도구가 어느 단계에서 사용되는지 구분하면 전체 흐름을 이해하기 쉽다.

## 개발 서버와 운영 서버는 목적이 다르다

개발할 때는 수정한 코드를 빠르게 확인할 수 있어야 한다. 현재 시스템에서는 Vite의 개발 서버를 사용한다.

`package.json`에는 개발 서버, 빌드, 미리보기를 실행하는 세 가지 명령이 등록되어 있다.

| 명령 | 역할 |
|---|---|
| `npm run dev` | 개발 서버 실행 (`vite`) |
| `npm run build` | 배포 파일 생성 (`vite build`) |
| `npm run preview` | 빌드 결과를 현재 PC에서 미리 제공해 확인 (`vite preview`) |

`preview`는 명령을 실행한 컴퓨터에서 빌드 결과를 제공한다. 개발 PC에서 실행하면 그 PC에서 배포 파일을 확인할 수 있다. 이 명령은 백엔드나 DB를 실행하지 않는다.

운영 환경에서는 사용자가 빌드된 파일을 받아 화면을 실행한다. 현재 구성은 이 파일을 FastAPI가 제공하는 방식이다. 사용자가 조작할 때마다 Vite가 코드를 다시 빌드하는 구조는 아니다. 배포 파일을 만들 때는 앞선 글의 레거시 플러그인과 CSS 처리 설정이 적용된다.

## 백엔드 기능도 개발 환경에서 확인할 수 있다

운영 서비스를 실행한 채 별도의 개발 환경에서 수정하고 확인할 수 있도록 구성할 수 있다. 같은 프로젝트를 별도 경로에 두고 개발용 FastAPI와 테스트 DB를 연결하는 방식이다.

| 구분 | 개발 환경 | 운영 환경 |
|---|---|---|
| 코드 | 수정·검증 중인 코드 | 배포한 코드 |
| 프론트엔드 | Vite 개발 서버 | 빌드된 파일 제공 |
| 백엔드 | 개발용 FastAPI | 운영용 FastAPI |
| 데이터 | 테스트 DB·파일 | 실제 운영 DB·파일 |

현재 Vite 설정에는 개발 중 API 요청을 FastAPI로 전달하는 프록시가 있다.

```js
server: {
  proxy: {
    '/api': 'http://localhost:8000',
  },
}
```

화면에서 `/api`로 시작하는 요청을 보내면 지정한 FastAPI로 전달한다. 따라서 백엔드 기능을 확인하기 위해 반드시 운영 환경에 접속해야 하는 것은 아니다.

다만 이 설정이 개발용·운영용을 알아서 구분하지는 않는다. 연결한 FastAPI가 어느 DB와 저장 폴더를 사용하는지도 확인해야 한다.

운영 코드 파일을 직접 수정하면 자동 재시작 설정에 따라 즉시 반영될 수 있고, 그렇지 않더라도 다음 재시작 때 적용된다. 개발 코드를 별도로 수정하고 확인한 뒤 배포해야 하는 이유다.

## React Router로 주소와 화면을 연결한다

다운로드, 업로드, 정보 관리 화면은 각각 다른 기능을 제공한다. 현재 시스템에서는 React Router로 URL과 화면 컴포넌트를 연결한다.

로그인 확인 등의 코드를 제외하고 관계만 남기면 다음과 같다.

```jsx
<BrowserRouter>
  <Routes>
    <Route path="/download" element={<DataDownload />} />
    <Route path="/params" element={<ParamExplorer />} />
  </Routes>
</BrowserRouter>
```

`/download`에서는 다운로드 화면을, `/params`에서는 정보 관리 화면을 표시한다. URL로 현재 화면을 구분하고 브라우저의 뒤로 가기·앞으로 가기와 연결할 수 있다.

여기서 화면을 이동하는 것과 화면에 필요한 데이터를 준비하는 것은 별개의 작업이다.

현재 다운로드 목록에서는 선택한 데이터셋 정보를 내보내기 화면으로 전달한다.

```jsx
navigate(`/download/export/${id}`, { state: row })
```

`row`에는 데이터 ID, 식별자, 날짜, 시간, 파라미터 정보 등이 들어간다. 계측 데이터 전체를 넘기는 것은 아니다.

목록을 거치지 않고 URL로 직접 진입하면 전달 정보가 없을 수 있다. 이때는 주소에 포함된 데이터셋 ID를 이용해 API에서 다시 조회한다. 직접 진입해도 화면이 동작하도록 준비한 것이다.

## Recharts로 미리보기 그래프를 구성한다

내보내기 화면에서는 파라미터 데이터를 그래프로 미리 볼 수 있다. 이때 Recharts를 사용한다.

Recharts는 선, 좌표축, 툴팁 등을 React 컴포넌트로 조합하는 차트 라이브러리다.

```jsx
<LineChart width={600} height={240} data={chartData}>
  <XAxis dataKey="x" />
  <YAxis />
  <Tooltip />
  <Line dataKey="v" />
</LineChart>
```

위 코드는 구조를 설명하기 위한 예시다. `chartData`는 표시할 데이터이고, `x`와 `v`는 각 데이터에서 읽을 값의 이름이다.

좌표축이나 선을 직접 그리지 않고 준비된 기능을 사용할 수 있다. 반면 라이브러리가 요구하는 데이터 형식과 설정 방법을 익혀야 하고, 기본 제공 범위를 벗어나는 동작은 추가로 구현해야 한다.

## 필요한 화면의 코드는 나중에 불러온다

내보내기 화면은 다음처럼 지연 로딩하도록 구성했다.

```jsx
const Export = lazy(() => import('./pages/Export'))
```

로그인이나 공지사항만 보는 사용자에게 처음부터 내보내기 화면과 차트 관련 코드를 모두 전달할 필요는 없다. 해당 화면을 처음 렌더링할 때 관련 코드를 불러오도록 나눈 것이다.

대신 처음 진입할 때 추가 파일을 받는 시간이 생길 수 있다. 현재 코드에는 로딩 안내와 파일 로드 실패 시 새로고침하거나 다른 화면으로 이동하는 처리도 들어가 있다.

추가 대기 시간은 네트워크와 서버 응답, 사용자 PC 성능, 캐시 등에 따라 달라진다. 초기 로딩이 얼마나 줄었는지 수치로 설명하려면 변경 전후를 같은 조건에서 측정해야 한다.

이 화면에서는 API 요청도 발생하므로 그래프가 표시될 때까지 걸린 시간 전체를 코드 로딩 시간으로 볼 수는 없다.

다음 글에서는 이 구성을 사용하면서 직접 설계해야 하는 상태 관리와 비동기 응답 처리 등을 살펴보려 한다.
