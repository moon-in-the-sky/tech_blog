# 02-2. 사내 구형 브라우저에서도 웹 화면을 사용할 수 있도록

앞선 글에서는 React의 기본 개념과 현재 시스템에 어떻게 적용했는지 살펴봤다. 이번에는 개발 과정에서 마주친 브라우저 호환성 문제를 정리하려 한다.

처음 웹 화면을 구축했을 때 화면 구성, 위치, 디자인 등 거의 모든 것이 깨져서 제대로 구현되지 않았다. 처음에는 이유를 몰랐지만 원인을 살펴보니 브라우저 버전으로 인한 문제였다. 이를 해결하기 위해 JavaScript 빌드 설정을 추가하고 CSS를 생성하는 방식도 조정했다.

이 글에서는 먼저 브라우저마다 문법과 기능의 지원 범위가 다르다는 점을 정리하고, 이어서 현재 시스템의 JavaScript와 CSS 구성을 설명한다.

## 브라우저마다 지원하는 문법과 기능이 다르다

웹 화면은 주로 HTML, CSS, JavaScript로 구성된다. 브라우저는 이 파일을 읽고 화면을 표시하거나 사용자 조작에 대응한다. 그런데 버전에 따라 이해하는 문법과 제공하는 기능이 다르다.

문법은 코드를 작성하고 해석하는 규칙이고, 코드는 그 규칙으로 작성한 실제 내용이다. 예를 들어 다음 코드는 사용자 이름을 읽는다.

```js
const name = user?.name
```

`?.`는 `user`가 `null`이나 `undefined`이면 오류 대신 `undefined`를 반환한다. 사용자 정보가 아직 없는 상황에서도 코드를 실행할 수 있도록 하는 문법이다.

화면에 무엇을 표시할지는 별도로 작성한다.

```jsx
<p>{user?.name ?? '로그인이 필요합니다'}</p>
```

이름이 있으면 이름을 표시하고, 없으면 대체 문구를 표시한다. 여기서 `??`는 왼쪽 값이 `null`이나 `undefined`일 때 오른쪽 값을 사용한다.

하지만 오래된 브라우저는 `?.` 자체를 해석하지 못할 수 있다. 이 경우 같은 뜻을 기존 문법으로 풀어 쓰는 방법이 있다.

```js
var name = user == null ? undefined : user.name
```

반면 코드는 읽을 수 있어도 필요한 기능이 없는 경우도 있다.

```js
var values = [10, 20, 30]
var last = values.at(-1)
```

`at()`는 배열에서 지정한 위치의 값을 가져오는 메서드다. `-1`은 뒤에서 첫 번째, 즉 마지막 값을 뜻한다. 브라우저에 이 메서드가 없다면 실행 중 오류가 발생한다.

따라서 문법 변환과 기능 보완을 구분해야 한다. 위 코드는 개념을 설명하기 위한 예시이며, 당시 발생한 오류가 이 문법이나 메서드 때문이었다는 뜻은 아니다.

## 폴리필은 없는 기능을 보완하는 코드다

폴리필은 브라우저에서 제공하지 않는 기능을 코드로 보완하는 구현이다. 표준에 정의된 동작을 미리 구현해두고 필요한 환경에서 함께 실행한다.

문법 변환 도구도 마찬가지다. `?.`를 어떤 코드로 바꿔야 하는지에 대한 규칙이 이미 구현되어 있다.

| 구분 | 하는 일 |
|---|---|
| 문법 변환 | 브라우저가 읽을 수 있도록 코드의 표현을 변경 |
| 폴리필 | 브라우저에 없는 메서드 등의 구현을 추가 |
| CSS 호환성 대응 | 지원하는 속성과 값으로 스타일을 조정 |

데이터가 없을 때 어떤 화면을 보여줄지는 폴리필이 아닌 애플리케이션에서 결정한다.

## Vite에서 구형 브라우저용 빌드를 구성했다

현재 시스템에서는 프론트엔드 개발과 빌드에 Vite를 사용한다. 개발할 때는 개발 서버에서 수정 내용을 확인하고, 배포할 때는 브라우저에 제공할 HTML·JavaScript·CSS 파일을 생성한다.

여기에 구형 브라우저 대응을 위해 `@vitejs/plugin-legacy`를 추가했다. 플러그인은 기존 도구에 기능을 추가하는 확장 모듈이다.

```js
import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'
import legacy from '@vitejs/plugin-legacy'

export default defineConfig({
  plugins: [
    react(),
    legacy({
      targets: [
        'Firefox >= XX',
        'Edge >= XX',
        'Chrome >= XX',
      ],
    }),
  ],
})
```

레거시 플러그인은 대상 브라우저에 맞춰 JavaScript를 변환하고 필요한 일부 폴리필을 포함한다. 브라우저의 지원 기능에 따라 적절한 파일을 불러오도록 로딩 코드도 생성한다.

`targets`는 구형 번들을 변환할 때 기준으로 삼는 브라우저 범위다. 지정하지 않으면 Browserslist 설정이나 플러그인의 기본 기준을 사용한다. 이 설정이 해당 브라우저에서의 동작을 검증해주지는 않는다.

ES 모듈, 동적 `import`, `import.meta`, 비동기 제너레이터를 지원하는 브라우저는 구형 번들이 아닌 최신 번들을 받는다. 최신 번들의 변환 기준은 `modernTargets`로 따로 정해지고, 기본값은 Chrome 64, Firefox 67, Edge 79 이상 등이다. 따라서 지원할 최저 버전의 브라우저가 최신 번들과 구형 번들 중 어느 쪽을 받는지 먼저 구분해야 한다.

이 방식은 원본 코드를 일일이 구형 문법으로 바꾸지 않고 대응할 수 있다는 장점이 있다. 대신 추가 파일과 폴리필이 생기고 빌드 설정도 관리해야 한다.

## CSS는 Tailwind 버전과 처리 구성을 조정했다

JavaScript를 변환해도 CSS 지원 문제는 남는다. 화면의 배치와 색상 등이 정상적으로 표시되려면 브라우저가 생성된 CSS도 이해해야 한다.

현재 스타일 작성에는 Tailwind CSS를 사용한다. 다음처럼 정해진 클래스 이름을 조합하면 해당 스타일의 CSS가 생성된다.

```jsx
<button className="text-white px-4 py-2 rounded-lg">
  저장
</button>
```

`text-white`는 글자색, `px-4`와 `py-2`는 좌우·상하 내부 여백, `rounded-lg`는 모서리 모양에 해당한다. 여기서 클래스는 HTML 요소에 붙이는 스타일 이름이다.

CSS 처리 구성은 다음과 같다.

```js
export default {
  plugins: {
    tailwindcss: {},
    autoprefixer: {},
  },
}
```

PostCSS를 통해 Tailwind가 CSS를 생성하고, Autoprefixer가 대상 브라우저에 필요한 접두사를 추가한다. Autoprefixer의 대상 브라우저는 Browserslist 설정으로 정해지며, Vite 레거시 플러그인의 `targets`와는 별도의 설정이다.

접두사는 다음의 `-webkit-`, `-moz-`처럼 특정 브라우저에서 사용하던 CSS 표기다.

```css
.example {
  -webkit-user-select: none;
  -moz-user-select: none;
  user-select: none;
}
```

접두사는 같은 기능의 다른 이름을 연결할 뿐, 브라우저에 없는 CSS 기능을 추가하지는 않는다. 따라서 Tailwind를 사용하더라도 특정 구형 브라우저에서 모든 스타일이 동작하는지는 직접 확인해야 한다.

## 빌드 설정과 실제 동작 확인은 별개다

현재 구성은 기존 React 코드와 스타일 작성 방식을 유지하면서 사내 브라우저 환경에 대응하기 위한 선택이다. 하지만 설정을 추가하는 것만으로 검증이 끝나지는 않는다.

레거시 대응은 주로 배포 빌드에 적용되므로 최종 빌드 결과를 대상 브라우저에서 확인해야 한다. 첫 화면뿐 아니라 화면 이동, 입력과 저장, 그래프 표시, 다운로드까지 확인할 필요가 있다.

현재 구성에서 JavaScript는 Vite 레거시 플러그인이, CSS는 Tailwind 3.4와 PostCSS가 담당한다. 둘은 별도의 설정이므로 각각 확인해야 한다. 다음 글에서는 Vite의 개발·배포 흐름과 함께, 화면 이동에 사용하는 React Router와 그래프를 표시하는 Recharts를 살펴보려 한다.
